Catact  v1.0.6
=================

把 GX Works3 的 FX5U 仿真器，变成威纶通 EBPro 能直接连的 Modbus TCP 设备。
没有真实 PLC 也能调 HMI 画面。


一、启动
--------
双击「Catact.exe」或「启动.bat」。

免安装版已内置 32 位 Python（python32 目录），不需要另外安装 Python。
如果 Windows/杀毒软件第一次拦截，选「允许运行」即可。


二、按顺序使用
--------------
1. GX Works3 打开 FX5U 工程 → 调试 → 模拟开始（先开仿真或先开桥都可以）
2. 本工具点工具栏「▶ 启动」（English 模式为「▶ Run」）启动桥，桥会自己等待并连接 GX 仿真
3. EBPro：设备类型 MODBUS TCP/IP、IP 127.0.0.1、端口 502、站号 1
4. 元件地址用「编辑 → 地址换算」（Edit → Address Converter）查：左边输 M0，
   右边自动出 0x 1；输 X0 出 0x 10001，输 Y10 出 0x 11009

四、地址规则
------------
  0x 可写位    1 – 8000      M0 – M7999
              8001 – 9000   S0 – S999
              9001 – 10000  B0 – B3E7（十六进制）
              10001 – 11000 X 可写镜像（X 是八进制）
              11001 – 12000 Y 可写镜像（Y 是八进制）
              12001 – 13000 T 触点镜像
              13001 – 14000 C 触点镜像
              14001 – 15000 L 镜像
              15001 – 16000 SM 镜像
              16001 – 17000 F 镜像
              17001 – 18000 ST 触点镜像
              18001 – 19000 SB 镜像（十六进制）
              （规则：0x 地址 = 1x 地址 + 10000）

  1x 只读位    1 / 1001 / 2001 / 3001 / 4001 / 5001 / 6001 / 7001 / 8001
               X / Y / T触点 / C触点 / L / SM / F / ST触点 / SB

  ★ 重要：0x 和 1x 的编号是**重叠但含义不同**的。
        0x 1 = M0，而 1x 1 = X0；0x 1009 = B8，而 1x 1009 = Y10。
        所以一个开关只能选一个区：按钮/开关用 0x（可读可写），
        指示灯也用同一个 0x 地址即可；1x 只用于只读监控。
    例：x0 开关 + x0 灯 → 都用 0x 10001
        x1 开关 + x1 灯 → 都用 0x 10002
        y10 开关 + y10 灯 → 都用 0x 11009
        m0 开关 + m0 灯 → 都用 0x 1

  4x 寄存器    1 / 8001 / 9001 / 10001 / 11001 / 12001 / 13001 / 21001 / 22001 / 30001
               D / W / T当前 / C当前 / ST当前 / SD / ZR / Z / R / SW

  记法：**按钮、数值输入 → 0x / 4x；指示灯、只看状态 → 0x（或 1x 只读监控）**。
  进制：X、Y 八进制；W、B、SB、SW 十六进制；其余十进制。
  例：M10 → 0x 11，S0 → 0x 8001，B0 → 0x 9001，X0 → 0x 10001，
      Y10 → 0x 11009，D100 → 4x 101，W1F → 4x 8032。
  ZR 在仿真器里读不到（会返回错误），需要文件寄存器请用 D 或 W。


五、写入日志怎么看（排查按钮问题）
----------------------------------
  按下 EBPro 里的按钮，然后看 Catact 的日志框，会看到下面四种之一：

  [写入] 0x 10001 → X0=1
      请求到了桥，并且已经写给仿真器。若画面仍不动，看下一条。

  [写入未生效] 0x 10001 → X0=1，回读=0
      写给仿真器了，但值没保持住。常见于：
        · X/Y 在仿真器里受输入/输出刷新控制，不允许外部写；
        · 梯形图里有双线圈、RST、PLS 等把它立刻改回。
      → 这种软元件不要把按钮绑上去；开关改用 M（如 M0 = 0x 1），
        再由梯形图用 M 去触发逻辑；或者用 GX Works3 的设备监视「强制」。

  [写拒绝] 0x 20000（不在地址表内）
      地址超出 0–19000。检查 EBPro 里填的地址。

  [地址提示] HMI 正在读 1x 1（X0），但这次写入落到了 0x 1（M0）……
      **最典型的「按下去就回弹」**：开关还绑在 1x 上。
      1x 是只读区，写进去的是同号的 M/S/B，读回来还是 X/Y，画面当然弹回。
      → 按提示把开关地址改成 0x 10001 / 0x 10002 / 0x 11009。

  如果按下去日志**一行都没有**，说明 EBPro 根本没发写入请求：
  检查元件是不是绑到了这个 MODBUS TCP/IP 设备、是不是模拟运行、
  元件有没有只填了「读地址」而没填「写地址」。


六、文件夹结构
--------------
  启动.bat
  Catact.exe           界面
  mx_bridge.py         桥（MX Component → Modbus TCP）
  python32\            32 位便携 Python（桥要用，界面不用）
  config.json          自动生成，保存端口/站号等设置
  modbus_debug.log     桥的写入/错误日志（与 mx_bridge.py 同目录）
  README.txt

整个文件夹拷走即可在别的电脑用（对方也要装 GX Works3 + MX Component）。


七、给别人用需要装什么
----------------------
必须装：MX Component（三菱官方组件）
        它提供 ActUtlType，任何程序要读 GX Simulator3 都绕不开它，
        没法打包进本工具（商业组件 + COM 注册 + 授权）。

        装完后在 Communication Settings Utility 里建一个逻辑站号：
            PC I/F    = GX Simulator3
            CPU type  = FX5U
            Port No.  = 0
            System No.= 1
            PLC No.   = 1
        本工具「设备 → 打开站号设置工具」可以直接调出这个界面。

不用装：Python（界面自带，桥用 python32 内置的）


八、常见问题
------------
  桥窗口一闪而过 / 启动失败
      → GX 仿真没在 RUN，或逻辑站号不是 1

  Open() 返回 0xF1000020
      → 上一次桥异常退出留下的占用，等 5 秒再点启动桥（程序已自动重试）

  「启动桥」按钮是灰的，点不动
      → 菜单「工具 → 启动桥」还能点，说明是旧版按钮状态卡死；v1.0.4 已修复：
        启动/停止只按「桥进程是否在跑」判断，停止后启动键必定恢复可点。
        502 被上次残留的桥占着时，直接点「启动桥」会自动清掉残留再启动。
        如果提示「被另一个 Catact 占用」，说明任务栏里还开着第二个窗口，关掉它即可。

  桥一直开着，GX 仿真停止后再启动，画面数据不动 / 状态灯还是绿的
      → v1.0.4 起桥会实时盯 FSimRun3.exe（PID + 启动时间），仿真一启动/重启就
        新建会话自动重连，并回读 D0 校验后才把灯变绿，不会再「假绿」。
        若等 5 秒还没连上，点「⟳ 刷新」手动补一次；仍然不行再「停止桥 → 启动桥」。

  EBPro 报 Device No Response
      → 设备类型选错（选成 MODBUS RTU 了），或端口不是 502

  数值不动
      → 元件「设备」没绑到这个 Modbus 设备，或地址算错

  开关按不下去 / 一按就回弹
      → 先看第五节日志；有 [地址提示] 就是地址还在 1x，
        没有日志就是 EBPro 没发写入，按第五节最后一段检查

  写了 D 寄存器但值不对
      → v1.0.1 已修复 FC16（多寄存器写入）偏移一个字节的问题

  关掉 Catact 以后 502 还被占用
      → v1.0.2 起桥会跟着主程序一起退出（1 秒内），不会再留残留进程；
        旧版本留下的残留，点一次「启动桥」就会自动清理
